# v1.18.2

## Secret Network v1.18.2 Instructions <a href="#secret-network-v1-18-2-upgrade-instructions" id="secret-network-v1-18-2-upgrade-instructions"></a>

### ⚠️ IMPORTANT NOTES ⚠️ <a href="#important-notes" id="important-notes"></a>

* All coordination efforts will be done in the "SN Validators" Telegram group.
* Make sure to [backup your validator](../maintaining-a-node-validator/validator-backup.md) before making any changes.
* **Please read carefully before you begin the upgrade.**

### ⚠️ Cosmovisor tool may NOT be used with this upgrade. This is due to the following facts:
* After the installation, the secret node should perform an additional step, BEFORE the actual network upgrade (more on this later).
  
## Upgrading Manually <a href="#upgrading-manually" id="upgrading-manually"></a>

### 1. Wait till the upgrade height is reached
When the network reaches the halt height, you'll see this message in your node's log (`journalctl -fu secret-node`):

```bash
2:00PM ERR UPGRADE "v1.18.2" NEEDED at height: ...
2:00PM ERR CONSENSUS FAILURE!!! err="UPGRADE \"v1.18.2\" NEEDED at height: ...
```

### 2. Stop the v1.18.1 node
```bash
sudo systemctl stop secret-node
```
⚠️ **Note**: Don't delete your current node installation package!
You'll need it. In fact, during the upgrade you'll have to install the newer Node, then fall back to the current one, and then reinstall the new node again!

### 3. Prepare for migration
```bash
# Remove migration files that could be left from previous migrations
rm /opt/secret/.sgx_secrets/migration_*

# Optional: get self target info. By such we'll rely on local attesattion rather than on remote during the migration
secretd migrate_op 5
```

### 4. Get the v1.18.2 binaries

This is the release page for testnet: [https://github.com/scrtlabs/SecretNetwork/releases/tag/v1.18.2-beta.5](https://github.com/scrtlabs/SecretNetwork/releases/tag/v1.18.2-beta.5)

In the following snippet we assume you run Ubuntu version 22.04 or hight,
hence we use `secretnetwork_1.18.2-beta.5_testnet_goleveldb_amd64_ubuntu-22.04.deb` package.
For older version use `secretnetwork_1.18.2-beta.5_testnet_goleveldb_amd64_ubuntu-20.04.deb`

```bash
wget "https://github.com/scrtlabs/SecretNetwork/releases/download/v1.18.2-beta.5/secretnetwork_1.18.2-beta.5_testnet_goleveldb_amd64_ubuntu-22.04.deb"
```

### 5. Install the v1.18.2 binaries, and produce the migration report

```bash
# install downloaded binary
sudo dpkg -i ./secretnetwork_1.18.2-beta.5_testnet_goleveldb_amd64_ubuntu-22.04.deb

# create self migration report
secretd migrate_op 1
```

### 6. Install the v1.18.1 binaries back, and proceed with the migration

```bash
# install v1.18.1 back
sudo dpkg -i ./secretnetwork_1.18.1-beta.3_testnet_goleveldb_amd64_ubuntu-22.04.deb

# export sealed data for the new version
secretd migrate_op 2
```

### 7. Install the v1.18.2 again, and finalize the migration

```bash
# install v1.18.2
sudo dpkg -i ./secretnetwork_1.18.2-beta.5_testnet_goleveldb_amd64_ubuntu-22.04.deb

# import sealed data
secretd migrate_op 3
```


### 8. Finally start the node
```bash
# re-apply any systemd unit file customizations

# Restart the node
sudo systemctl restart secret-node
```

After restarting the node with v1.18.2, you should see `INF applying upgrade "v1.18.2" at height: ...` in the logs (`journalctl -fu secret-node`). Once 67% of voting power comes online, you'll see blocks executing again.

## In Case of an Upgrade Failure <a href="#in-case-of-an-upgrade-failure" id="in-case-of-an-upgrade-failure"></a>

In the event of an issue at upgrade time, we should coordinate via the "SN Validators" Telegram group.

If as a result of a software bug the network fails to produce new blocks with the v1.18.2 binaries, the SCRT Labs team will distribute a v1.18.1 binary with a replacement v1.18.2 upgrade handler, which will allow the chain to revert to v1.18.1 while continuing to produce new blocks.
