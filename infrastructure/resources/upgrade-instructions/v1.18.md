### ⚠️ IMPORTANT NOTES ⚠️ <a href="#important-notes" id="important-notes"></a>

* All coordination efforts will be done in the "SN Validators" Telegram group.
* Make sure to [backup your validator](../maintaining-a-node-validator/validator-backup.md) before making any changes.
* **Please read carefully before you begin the upgrade.**

### ⚠️ Cosmovisor tool may NOT be used with this upgrade. This is due to the following facts:
* After the installation, the secret node should perform an additional step, BEFORE the actual network upgrade (more on this later).
  
## Upgrading Manually <a href="#upgrading-manually" id="upgrading-manually"></a>

### 1. Wait till the upgrade height is reached
When the network reaches the halt height, you'll see this message in your node's log (`journalctl -fu secret-node`):

```bash
2:00PM ERR UPGRADE "v1.18" NEEDED at height: ...
2:00PM ERR CONSENSUS FAILURE!!! err="UPGRADE \"v1.18\" NEEDED at height: ...
```

### 2. Stop the v1.17 node
```bash
sudo systemctl stop secret-node
```


### 3. Get the v1.18 binaries

This is the release page: [https://github.com/scrtlabs/SecretNetwork/releases/tag/v1.18.0](https://github.com/scrtlabs/SecretNetwork/releases/tag/v1.18.0)

In the following snippet we assume you run Ubuntu version 22.04 or hight,
hence we use `secretnetwork_1.18.0_mainnet_goleveldb_amd64_ubuntu-22.04.deb` package.
For older version use `secretnetwork_1.18.0_mainnet_goleveldb_amd64_ubuntu-20.04.deb`

```bash
wget "https://github.com/scrtlabs/SecretNetwork/releases/download/v1.18.0/secretnetwork_1.18.0_mainnet_goleveldb_amd64_ubuntu-22.04.deb"
```


### 4. Install the v1.18 binaries

```bash
sudo apt install -y "./secretnetwork_1.18.0_mainnet_goleveldb_amd64_ubuntu-22.04.deb"
```

### 5. Migrate your local sealed files to `mrenclave` sealing
This step must be done manually, before the Node is started

```bash

# IMPORTANT: Import several files sealed with mrsigner sealing into a single file sealed with mrecnalve sealing
secretd migrate_op 4
```

### 6. Finally start the node
```bash
# re-apply any systemd unit file customizations

# Restart the node
sudo systemctl restart secret-node
```

### 7. Optionally - move older sealed files into a backup directory

```bash
mkdir /opt/secret/.sgx_secrets/legacy
mv /opt/secret/.sgx_secrets/*.sealed /opt/secret/.sgx_secrets/legacy/
```

After restarting the node with v1.18, you should see `INF applying upgrade "v1.18" at height: ...` in the logs (`journalctl -fu secret-node`). Once 67% of voting power comes online, you'll see blocks executing again.

## In Case of an Upgrade Failure <a href="#in-case-of-an-upgrade-failure" id="in-case-of-an-upgrade-failure"></a>

In the event of an issue at upgrade time, we should coordinate via the "SN Validators" Telegram group.

If as a result of a software bug the network fails to produce new blocks with the v1.18 binaries, the SCRT Labs team will distribute a v1.17 binary with a replacement v1.18 upgrade handler, which will allow the chain to revert to v1.17 while continuing to produce new blocks.
