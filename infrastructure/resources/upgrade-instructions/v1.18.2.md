# v1.18.2

## Secret Network v1.18.2 Instructions <a href="#secret-network-v1-18-2-upgrade-instructions" id="secret-network-v1-18-upgrade-instructions"></a>
  
## Upgrading Manually <a href="#upgrading-manually" id="upgrading-manually"></a>

Since this is an emergency (a.k.a. offline) upgrade, no need to wait for the upgrade height. Moreover, there's no need to perform this upgrade on all the nodes.
It's sufficient to test it on a single node.

### 1. Stop the v1.18.1 node
```bash
sudo systemctl stop secret-node
```
⚠️ **Note**: Don't delete your current node installation package!
You'll need it. In fact, during the upgrade you'll have to install the newer Node, then fall back to the current one, and then reinstall the new node again!

### 2. Prepare for migration
```bash
# Remove migration files that could be left from previous migrations
rm /opt/secret/.sgx_secrets/migration_*

# Optional: get self target info. By such we'll rely on local attesattion rather than on remote during the migration
secretd migrate_op 5
```
### 3. Get the v1.18.2 binaries

This is the release page for testnet: [https://github.com/scrtlabs/SecretNetwork/releases/tag/v1.18.2-beta.1](https://github.com/scrtlabs/SecretNetwork/releases/tag/v1.18.2-beta.1)

In the following snippet we assume you run Ubuntu version 22.04 or hight,
hence we use `secretnetwork_1.18.2-beta.1_testnet_goleveldb_amd64_ubuntu-22.04.deb` package.
For older version use `secretnetwork_1.18.2-beta.1_testnet_goleveldb_amd64_ubuntu-20.04.deb`

```bash
wget "https://github.com/scrtlabs/SecretNetwork/releases/download/v1.18.2-beta.1/secretnetwork_1.18.2-beta.1_testnet_goleveldb_amd64_ubuntu-22.04.deb"
```

### 4. Install the v1.18.2 binaries, and produce the migration report

```bash
# install downloaded binary
sudo dpkg -i secretnetwork_1.18.2-beta.1_testnet_goleveldb_amd64_ubuntu-22.04.deb

# create self migration report
secretd migrate_op 1
```

### 5. Install the v1.18.1 binaries back, and proceed with the migration

```bash
# install v1.18.1 back
sudo dpkg -i secretnetwork_1.18.1-beta.3_testnet_goleveldb_amd64_ubuntu-22.04.deb

# export sealed data for the new version
secretd migrate_op 2
```

**Note:** the above migration is supposed to fail, because no appropriate on-chain upgrade proposal was accepted, hence the migration target is not eligible for the secrets handover.
This is where emergency upgrade procedure comes into play.
